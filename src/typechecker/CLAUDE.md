# typechecker/

Static type-checking pass over the parsed AST, before interpretation.

## Status
Implemented. `TypeChecker::new().check_program(&[Stmt]) -> Result<(), TypeError>`.
Single-parent class inheritance with flattening (no `super` keyword, child must assign all inherited fields in initializer).

## Layout
- **`mod.rs`** (439 lines) — module root: `Type` enum + `Display`/`from_annotation_name`, `TypeError`, `FunctionSig`/`ClassInfo`, `TypeChecker` struct and `new()`/`check_program()`, scope helpers (`push_scope`/`pop_scope`/`declare_var`/`lookup_var`/`resolve_type`), `assignable` helper (type compatibility: equality, empty-array sentinel, nil-into-pointer), and the test suite. Public API: `Type`, `TypeError`, `TypeChecker`.
- **`classes.rs`** — class-related checking and inheritance: `collect_classes` (three-pass: register names, fill own members, flatten inheritance), `flatten_inheritance` (merges parent fields/methods into children, detects unknown parents and cycles), `visit_class_for_cycle` (DFS cycle detection), `check_classes` (method body checking), `check_fields_assigned_in_initializer` (field assignment validation for own + inherited fields), `check_field_access` (field type resolution), `check_method_call` (method dispatch and `.new()` construction), helper functions `collect_assigned_names`, `collect_parent_field_decls_recursive`, `method_name`.
- **`calls.rs`** — function/method/builtin call checking: `collect_function_signatures` (top-level function pre-registration), `check_call` (free function dispatch), `check_call_args` (shared arity/type validation), `check_array_builtin` (builtin dispatcher with arity check + function-pointer dispatch), plus per-builtin checking functions `check_len`/`check_push`/`check_get`/`check_set`/`check_pop` (array builtins), `check_alloc`/`check_deref`/`check_set_deref`/`check_free` (pointer builtins), and `check_collect` (GC mark-and-sweep builtin, takes no args, yields `Integer` freed-slot count). Each `CheckFn` is wired into the registry via `src/builtins.rs` function pointers.
- **`methods.rs`** — primitive-method checking: `check_primitive_method` (dispatcher by `ReceiverKind` + method name), plus 24 individual `MethodCheckFn`s implementing type rules for each primitive method (Array `size`/`push`/`get`/`set`/`pop`, String `size`/`to_i`/`to_f`, Integer `to_s`/`to_f`, Float `to_i`/`to_s`, Boolean `to_s`, Pointer `deref`/`set_deref`/`free`, and conversion methods `to_s`/`to_i`/`to_f` shared across receiver kinds). Registry in `src/methods.rs` maps `(ReceiverKind, name)` tuples to check/eval function pointers.
- **`expressions.rs`** (195 lines) — expression-level checking: `check_expr` (main recursive dispatcher over all `Expr` variants), `check_binary_op` (operator type rules), `binop_symbol` (operator display helper).
- **`statements.rs`** (323 lines) — statement-level checking: `check_stmt` (main recursive dispatcher over all `Stmt` variants), `check_block` (block type checking), `check_body_return_type` (function body return type), `check_tail_stmt` (tail-position statement type), `combine_tail_types` (branch type reconciliation).

## Design
- `Type` enum: `Integer, Float, Boolean, String, Nil, Array(Box<Type>), Instance(String), Pointer(Box<Type>)` — the canonical (post-alias-normalization) names from `ast::TypeAnnotation`.
- **Classes & Inheritance**: `ClassInfo { fields: HashMap<String, Type>, methods: HashMap<String, FunctionSig> }` per class name in `self.classes`, built by `collect_classes` in three passes:
  - **Pass 1**: Register every class *name* with an empty `ClassInfo` (so annotations can reference any class regardless of declaration order, including self-reference).
  - **Pass 2**: Fill in each class's own field/method types (not yet including inherited members).
  - **Pass 3** (Flattening): For each child class, merge the parent's (now fully-flattened) fields/methods into the child's maps via `flatten_inheritance`. Child members override parent members (implicit override, no keyword). Also detects unknown parent names and inheritance cycles, reporting errors at the child's `ClassDef` position. After this pass, every class's `ClassInfo.fields`/`methods` contains both its own members and all inherited members transitively.
  
  `resolve_type` treats any name in `self.classes` as `Type::Instance(name)`, so a field/param/return annotation naming a class works exactly like a builtin type annotation.
- `fields` merges both `const` decls and instance-var (`FieldDecl`) declarations into one map — both are accessed unqualified inside methods (implicit `self`), so the typechecker doesn't distinguish them after `collect_classes`. Class consts *require* an explicit type annotation (`TypeError` if omitted) since there's no other way to know the field's type up front.
- `check_classes` type-checks every method body (including `initializer`) by pushing a scope, pre-declaring all of the class's field types into it (as if they were already-bound local vars), then declaring params on top (so a param can shadow a same-named field within that method) and running the ordinary `check_body_return_type`. This is *why* `count = number` inside `initializer` type-checks against the field's declared type: it's just an ordinary `VarDecl`-shaped assignment into a scope that already has `count: Integer` declared in it — see the soundness caveat below.
- `Expr::FieldAccess`/`Stmt::FieldAssign` both go through `check_field_access`, which requires the object's type to be `Type::Instance` and the field to exist in that class's `fields` map.
- `Expr::MethodCall` (`check_method_call`) special-cases a bare `Expr::Ident` `object` that names a class (and has no bound variable of that name — `lookup_var` is checked first) as `ClassName.new(args)` construction (`check_construction`): validates args against the class's `initializer` signature if one exists (arity must be 0 with a helpful error if there's no initializer and args were passed), and returns `Type::Instance(class_name)`. Otherwise it type-checks as an ordinary instance method call with a fallthrough: (1) if object is `Type::Instance`, look up method in that class's flattened `methods` map, type-check via `check_call_args` and the method's signature, or (2) if object is any other type (Array/String/Integer/Float/Boolean/Pointer), try `methods::ReceiverKind::of_type` to lift the type to a receiver kind, then dispatch via `check_primitive_method`; otherwise, error "no method `name` for type `X`".
- **Arrays**: no generic `Array<T>` syntax — each element type gets its own concrete annotation name instead (`IntArray`, `FloatArray`, `BoolArray`, `StringArray`, resolved in `Type::from_annotation_name`), Pascal-array style. No array-of-array annotation exists, so nested collections can't be typed (the parser *would* accept `xs[0][1]` syntactically, but `check_expr`'s `Expr::Index` arm would reject indexing into whatever non-array type `xs[0]` turns out to be). `examples/data_structures/graph.yara` works around this by using an edge-list of two parallel `IntArray`s instead of an adjacency-list-of-lists.
- Array literal `[1, 2, 3]`: element type inferred from the first element, all others must match (`TypeError` "array elements must share one type"). Empty literal `[]` can't infer anything — `check_expr` returns a sentinel `Array(Nil)`, and `VarDecl`/`ConstDecl` special-cases that sentinel as compatible with any declared array annotation (so `xs: IntArray = []` works), then stores the *declared* type, not the sentinel, so the variable's real element type is known from then on.
- `arr[i]` (`Expr::Index`): index must be `Integer`; result type is the array's element type.
- Array and pointer builtins are checked in `check_array_builtin`, called from `Expr::Call` before falling through to user-defined function lookup — same ad-hoc pattern as `print`, not real functions in the `functions` table. Their registry is in `src/builtins.rs`: `check_array_builtin` does one registry-driven arity check up front, then dispatches via function pointer to the per-builtin `CheckFn` (e.g., `check_len`, `check_push`), each implementing only its own type rules. Array builtins `len`/`push`/`get`/`set`/`pop` (e.g., `push`/`set` require the value argument's type to match the array's element type exactly). Pointer builtins: `alloc(x: T) -> Ptr<T>`, `deref(p: Ptr<T>) -> T`, `set_deref(p: Ptr<T>, v: T) -> Nil`, `free(p: Ptr<T>) -> Nil` (each checked for pointer type and inner-type agreement). The unified registry ensures both stages implement the same set of builtins at compile time via missing-field errors.
- **Pointers**: `Ptr<T>` annotations arrive as name strings from the parser (e.g. `"Ptr<Integer>"`, nested like `"Ptr<Ptr<String>>"`), decoded recursively in `Type::from_annotation_name`. Inner types can be primitive types *or* user-defined classes (e.g. `Ptr<Node>`), resolved via the class table in `resolve_type`. Nil is assignable to any `Ptr<T>` via the `assignable` helper (type compatibility check). The pointer builtins provide opt-in manual-memory management: `alloc` allocates a heap cell, `deref` retrieves the value, `set_deref` updates it, and `free` deallocates. Free-and-then-deref is a runtime error (use-after-free becomes visible and diagnosable, not undefined behavior) — the pedagogical point of an interpreter-modeled heap. Dereferencing or freeing `nil` is also a runtime error.
- Function signatures collected in a pre-pass (`collect_function_signatures`) before checking bodies, so forward references / call order doesn't matter.
- Scoping: `env: Environment<Type>` (the shared `src/env.rs` scope stack), with `push_scope`/`pop_scope`/`declare_var`/`lookup_var` as thin delegators around function bodies and `for` loops; `lookup_var` searches innermost-out. The interpreter uses the same `Environment` over `Value` — same container, separate check-vs-eval logic.
- No implicit numeric coercion: `Int + Float` is a type error (`check_binary_op`). `String + String` is the only cross-type special case (concatenation).
- Comparisons (`< > <= >=`) require matching numeric operands and yield `Boolean`; `==`/`!=` require matching types of any kind.
- `if`/`elsif`/`while` conditions must be exactly `Boolean`.
- `for x in a..b` requires both bounds `Integer`; loop var bound as `Integer` in a pushed scope.
- Function return-type check compares the declared return type against the type of the body's final expression (implicit last-expr return) or an explicit trailing `return expr` — see `check_body_return_type`. A trailing `if`/`elsif`/`else` is itself treated as a tail expression (`check_tail_stmt`): each branch's own tail type is computed recursively (`check_body_return_type` on the branch), and all branches present must agree via `combine_tail_types` (mismatch is a `TypeError`, "branches of `if` return different types"). If there's no `else`, the `if`'s tail type is `None` (can't guarantee every path yields a value), which skips the declared-vs-actual comparison rather than erroring — needed for e.g. `factorial`'s `if n <= 1 ... else ... end` as the whole body.
- Unary negation (`-x`): operand must be `Integer` or `Float`; result is the same type. No other unary operator exists.
- Free calls are handled by `check_call` (extracted from `check_expr`'s `Expr::Call` arm, mirroring the interpreter's `call_function`): `print` first (ad hoc, accepts any args, returns `Nil`), then array builtins, then user functions in the `functions` table. Add real built-ins the same way until a stdlib design exists.
- **Definite-assignment check (classes)**: `check_fields_assigned_in_initializer` checks that every instance-variable field — both those declared in this class *and* those inherited from parent classes — is assigned somewhere in the initializer (via helper `collect_assigned_names`, a flow-insensitive recursive walk of `Stmt::VarDecl` and `Stmt::FieldAssign`). Conditional assignment (inside an `if` branch) counts as assigned, deliberate over-approximation. Since there's no `super` keyword, child initializers must assign all inherited fields themselves. A class with instance-var fields but no initializer is an error. This closes the soundness gap: fields must be assigned before use.
- Errors (`TypeError`) carry line/column same shape as `LexError`/`ParseError`: `Display` = `"{line}:{column}: {message}"`.

## Gotchas
- Return-type-mismatch errors report the enclosing `def`/method's own position via `Stmt::line()`/`Stmt::column()` (the shared `ast` helpers) rather than re-destructuring `Stmt::FunctionDef` at the error site.
- Unknown type names in annotations (e.g. a typo) surface as `TypeError` at check time, not parse time — parser accepts any identifier as a type name. This is also how you'd misspell a class name in an annotation — same error, "unknown type `X`".
- **Inheritance**: single parent only (no multiple inheritance), flattening at check time (all members merged into child's `ClassInfo`), child fields/methods override parent ones (implicit override), no `super` keyword (child initializer must assign all inherited fields). Unknown parent names and inheritance cycles detected and reported at child's `ClassDef` position. After flattening, all lookups (`check_field_access`, `check_method_call`) transparently see inherited members (they use the flattened `ClassInfo`).
