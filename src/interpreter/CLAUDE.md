# interpreter/

Tree-walk evaluator executing a typechecked AST.

## Status
Implemented. `Interpreter::new().run_program(&[Stmt]) -> Result<(), RuntimeError>`. Wired into `main.rs` (`yara run <file>` executes lexer to parser to typechecker to interpreter in sequence, bailing with the first error).

## Layout
Split into submodules for cohesive organization (behavior-preserving refactor):
- **`mod.rs`** (556 lines) — module doc, `Value` enum + Display, `RuntimeError` + Diagnostic impl, `StackFrame`, `FunctionDecl`, `ClassDecl`, `Flow`, `Interpreter` struct, `new()`/`run_program()`, scope helpers (declare_var/set_var/lookup_var/push_scope/pop_scope), submodule declarations, and unit tests.
- **`expressions.rs`** (269 lines) — expression evaluation: `eval_expr`, `eval_bool`, `eval_int`, `array_get`, `eval_binary_op`.
- **`statements.rs`** (195 lines) — statement execution and control flow: `exec_stmt`, `exec_block`, `exec_function_body`, `exec_tail_stmt`.
- **`calls.rs`** — function calls and builtins: `call_function`, `call_array_builtin` (builtin dispatcher with function-pointer dispatch), plus per-builtin evaluation functions `eval_len`/`eval_push`/`eval_get`/`eval_set`/`eval_pop` (array builtins), `eval_alloc`/`eval_deref`/`eval_set_deref`/`eval_free` (pointer builtins), and `eval_collect` (GC mark-and-sweep builtin). Each `EvalFn` is wired into the registry via `src/builtins.rs` function pointers. Also contains `collect_garbage` and `mark_value` (GC helper methods on `Interpreter`).
- **`classes.rs`** (141 lines) — class/instance handling: `construct`, `call_method`, `run_method`.

## Design
- `Value` enum: `Integer, Float, Boolean, String, Nil, Array(Rc<RefCell<Vec<Value>>>), Instance(Rc<RefCell<HashMap<String, Value>>>, String), Pointer(usize)` — runtime counterpart of `typechecker::Type`, but this crate stays decoupled from that module (no shared type).
- **Classes**: `ClassDecl { const_inits: Vec<(String, Expr)>, field_names: Vec<String>, methods: HashMap<String, FunctionDecl> }` per class, collected in `run_program` alongside top-level function collection. `Value::Instance` uses the same `Rc<RefCell<..>>` reference-semantics trick as `Value::Array` — a field map shared between every binding of the same instance, so `alias.count = 42` after `alias = h` mutates `h.count` too.
- `construct` (`ClassName.new(args)`): builds a fresh `HashMap`, evaluates each class const's value expression *in declaration order* (re-declaring already-computed consts into a scratch scope before each one, so a later const's initializer can reference an earlier const by bare name), zero-fills declared instance vars to `Value::Nil`, then — if the class has an `initializer` — runs it via `run_method` with `args` bound to its params. Instantiation of a class with no `initializer` skips straight to returning the (all-`Nil`-fielded) instance; the typechecker already guarantees no args were passed in that case.
- `run_method` is the implicit-`self` mechanism: it **copies** the instance's current field values into the method's own pushed scope (so bare names resolve exactly like any other local, letting `count = number` "just work" as an ordinary assignment), executes the body, then **copies back** whatever those same field-name keys hold in the scope afterward into the instance's shared field map. This is a snapshot-copy approach rather than a persistent "current `self`" reference threaded through `eval_expr`/`exec_stmt` — simpler to implement, correct given `if`/`while` don't push their own scopes (only `for` and calls do, and `for` always pops before returning), but means a field mutated *inside a nested function call made from a method* wouldn't be seen (methods don't currently call arbitrary top-level functions that could indirectly mutate `self` by name — only by taking the instance value itself and going through `.field =`/`set_var`\-style paths that operate on the `Rc` directly, which works fine).
- `call_method`/`construct` both funnel through `run_method`; `Expr::MethodCall` (`eval_expr`) special-cases a bare `Expr::Ident` `object` that names a class (and has no bound variable shadowing it — `lookup_var` checked first) as `.new` construction, otherwise evaluates `object` normally and calls `call_method`.
- Call-stack frames for methods use `format!("{class_name}#{method_name}")` / `format!("{class_name}.new")` so a `RuntimeError`'s trace reads naturally (e.g. `in \`Hello#area\` at 12:3`).
- **Pointers/heap**: an opt-in manual-memory feature teaching memory management. `Value::Pointer(usize)` is an index into `Interpreter::heap` (a `Vec<Option<Value>>`), not a Rust reference. The builtin `alloc(value)` pushes a slot into the heap and returns its index; `deref(ptr)` reads it, `set_deref(ptr, value)` mutates it, and `free(ptr)` empties the slot by setting it to `None`. Dereferencing a freed slot is a `RuntimeError` ("use after free") rather than UB — the teaching point is to make allocation and deallocation *visible and diagnosable*. Double-free is also caught as a `RuntimeError`. Dereferencing `nil` (a null pointer) is also a `RuntimeError` ("nil pointer dereference: `deref` on `nil`"; similarly for `set_deref`). Freeing `nil` is a `RuntimeError` ("cannot `free` a nil pointer"). Slots are never reused, so a stale pointer reliably reports an error. `Value::Pointer` displays as `ptr#<idx>` for clarity in error messages. All four pointer builtins live in `call_array_builtin` alongside the array builtins (both matched by the shared `builtins` registry).
- **Teaching GC**: the `collect()` builtin (also in `call_array_builtin`) runs `collect_garbage`, a mark-and-sweep pass over the same heap. Mark: every binding in every live scope (`Environment::iter_values`) is a root; `mark_value` chases roots recursively through array elements, instance fields, and pointee heap slots (a slot can hold a pointer/array/instance, so reachability cascades), with `Rc`-identity `seen` guards so cyclic containers terminate. Sweep: unmarked still-allocated slots become `None` (exactly what `free` does) and the freed count is returned as `Value::Integer` — a program can print what a collection reclaimed next to its manual-`free` twin.
- **Arrays have reference semantics** (like Python lists), via `Rc<RefCell<Vec<Value>>>`: cloning a `Value::Array` (e.g. passing it as a function argument) shares the same backing storage, so `push`/`set`/`pop` inside a called function are visible to the caller. This is *the* mechanism that makes the arena-style linked-list/tree/graph examples work without a real pointer type — see `examples/data_structures/`. Every other `Value` variant (except `Pointer`, which is an index) is copied by value on clone.
- Array and pointer builtins (`call_array_builtin`, called from `call_function` before user-defined function lookup, same ad-hoc pattern as `print`): gated on the shared `builtins` registry (`src/builtins.rs`), which dispatches via function pointer to the per-builtin `EvalFn` (e.g., `eval_len`, `eval_push`). Any name not in the registry returns early so the caller falls through to user functions. Arity is *not* re-checked here (the typechecker already enforced it via the same registry). Array builtins: `len` (borrow, `.len()`), `push` (`borrow_mut().push(..)`), `pop` (`borrow_mut().pop()`, `RuntimeError` "cannot `pop` from an empty array" if empty), `get`/`set` share bounds-checking logic with `arr[i]` indexing (`array_get`) — out-of-bounds is a `RuntimeError` with the index and length in the message, not a panic. Pointer builtins: `alloc` (push to heap, return index), `deref` (read slot), `set_deref` (mutate slot), `free` (empty slot); all check for freed/invalid slots and error with clear messages.
- `arr[i]` (`Expr::Index`) evaluates the array and index, then defers to `array_get`, the same helper the `get` builtin uses.
- Scoping mirrors typechecker: `env: Environment<Value>` (the shared `src/env.rs` scope stack, same type the typechecker uses over `Type`), pushed/popped around function calls and `for` loops. `push_scope`/`pop_scope`/`declare_var`/`lookup_var`/`set_var` are thin delegators onto it; `run_method`'s implicit-`self` copy-back reads the innermost scope via `env.current()`.
- `set_var` (used by `Stmt::VarDecl`/`ConstDecl`) walks the scope stack looking for an existing binding to mutate in place (needed for `x = x + 1` inside a `while` body to actually mutate the outer `x` rather than shadow it); falls back to declaring in the current scope if not found.
- Function calls: `call_function` pushes a `StackFrame { function_name, line, column }` onto `call_stack` before executing the body and pops it after — this is what populates `RuntimeError.call_stack` for the trace.
- **Implicit last-expression return** (Ruby-style): `exec_function_body` delegates its trailing statement to `exec_tail_stmt`, which special-cases `Stmt::ExprStmt` (evaluate directly) and trailing `if`/`elsif`/`else` (recurse into whichever branch's body via `exec_function_body` again, so a nested trailing `if` inside that branch also works) to become the call's value — mirroring `typechecker::check_tail_stmt`/`check_body_return_type`. If these two ever diverge, return-value bugs slip past the typechecker. Explicit `return expr` still works via `Flow::Return` short-circuiting through `exec_block`.
- Unary negation (`-x`): `Integer` and `Float` only; anything else is a `RuntimeError` (typechecker should already have rejected it, this is a defense-in-depth check).
- `print(...)` is a built-in special-cased in `call_function` (joins args with a space via `Value`'s `Display`, `println!`s), same ad-hoc pattern as the typechecker's `print` handling — keep both in sync if a real stdlib/builtin registry replaces this.
- `RuntimeError::Display` prints rustc-adjacent multi-line output: message, `at line:column`, then each call-stack frame reversed (innermost first).

## Gotchas
- Division by zero is checked only for `Integer / Integer` (float division by zero silently yields `inf`/`NaN`, matching IEEE 754 — revisit if that's undesirable for a "friendly errors" language).
- `exec_function_body` duplicates the "is this the last statement" logic from `typechecker::check_body_return_type` — any AST changes to `Stmt` must update both in lockstep. The `tail_if_return_value_agrees_across_stages` test runs tail-`if` programs (plain/elsif/nested/recursive) through *both* the typechecker and interpreter and asserts the computed value, so a divergence surfaces as a failing test.
- Instance vars start life as `Value::Nil` until something assigns them (no "definitely assigned" tracking — matches the typechecker's known gap, see its `CLAUDE.md`); reading one too early just silently gets `Nil` rather than erroring.
- No inheritance — `call_method`/`construct` only ever look at the exact class name stored in `Value::Instance`.
